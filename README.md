# Rust Practice

一点古法 Rust 练习，具体的来讲，我写一个简单的计算器得了。

其实这东西没啥意义，只不过是练习而已。


## 分层

三层职责，但切法和最初设想略有不同：把**状态**单独拎出来，把"传递层"重新定义成"事件翻译 + 状态迁移"。

| 层 | 职责 | 知道什么 | 不许知道什么 |
| --- | --- | --- | --- |
| 界面层 | 读状态画界面；把点击翻译成事件 | 状态、事件、egui | 计算规则、状态迁移规则 |
| 模型层 | 定义状态与事件；实现状态迁移（状态机） | 事件、计算层 | egui、像素、按钮位置 |
| 计算层 | 纯函数：运算 → 结果或错误 | 数字与运算符 | 状态、事件、界面 |

依赖方向**只向内**：

```text
main  →  ui  →  model  →  calc
```


## 状态机


- **立即执行式（实物计算器式）**：`1` `+` `2` `=`，每次按运算符就结算上一步。状态机是主角，计算层很薄。
- **表达式求值式**：输入 `1 + 2 * 3` 再整体求值。需要分词与带优先级的解析，状态机很薄。

**选立即执行式。** 它跟按钮 UI 天然契合，状态机是真正要练的东西，而且能做完。表达式求值式列为 V2（见"里程碑"），到时候正好用它来验收分层是否成立。

### 状态

状态只有一个来源，由模型层独有：

| 字段 | 含义 |
| --- | --- |
| `display` | 当前显示的内容（存**文本**，不是数字，见下） |
| `accumulator` | 已确认的上一个操作数 / 累计值 |
| `pending` | 待处理的运算符，可能没有 |
| `phase` | 当前处于哪个阶段 |
| `last_op` / `last_operand` | 连续按 `=` 时重复上一次运算用（可选，V2） |

四个阶段：

| 阶段 | 含义 |
| --- | --- |
| `Input` | 正在输入一个数字，下一个数字键是**追加** |
| `AwaitingOperand` | 刚按完运算符，等新操作数，下一个数字键是**替换** |
| `Done` | 刚算完一个结果，下一个数字键是**开启新计算** |
| `Error` | 出错了，除 `C` 外所有键都被忽略 |

`Input` 和 `AwaitingOperand` 的区别只有一条：`display` 里放的**是你正在输入的操作数**，还是**上一个操作数或上一个结果**。这一条决定了数字键是追加还是替换。

### 事件

界面翻译出来的领域事件，收敛成五六个就够：

- `Digit(0..=9)`
- `Dot`
- `Operator(+ - * /)`
- `Equals`
- `Clear`
- `Backspace`

事件类型定义在模型层——它是模型"能被怎么指挥"的词汇表，不是界面层的东西。


## 主流程

### 启动

1. `main` 建立初始状态（`display = "0"`，`phase = Input`，其余为空）。
2. 把状态交给 eframe 的启动函数，它创建窗口并**接管事件循环**——控制权交给框架，你的代码不再有"主循环"。
3. 之后每一步都是框架回调你的代码。

### 每一帧

egui 是**立即模式**：它每帧都把整个界面重画一遍


## 文件结构

```text
rust-practice/
├── Cargo.toml
├── Cargo.lock          # 提交进仓库（可执行的程序要提交）
├── README.md           # 本文档
├── LICENSE
├── .gitignore          # /target
└── src/
    ├── main.rs         # 入口：只负责启动，不含任何业务逻辑
    ├── lib.rs          # 库根：声明模块，把逻辑暴露出去
    ├── calc.rs         # 计算层：纯函数，最薄但最该有测试
    ├── model.rs        # 模型层：状态 + 事件 + 迁移规则（状态机）
    └── ui.rs           # 界面层：egui 绘制 + 点击翻译成事件
```
